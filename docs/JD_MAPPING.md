## Resume project name

**Retail Bank Customer 360 & Risk Analytics | SQL, DuckDB, Python, Streamlit**

## Draft resume bullets — use only after the referenced deliverable is complete

- Built a reproducible DuckDB analytical warehouse that integrates eight relational banking tables into customer, account, transaction, product, and lending-risk marts.
- Authored tested SQL using multi-table joins, CTEs, window functions, and cohort logic to define portfolio, engagement, product-penetration, and risk metrics.
- Developed an interactive Streamlit/Plotly decision dashboard for customer segmentation, account-activity retention, transaction behaviour, and loan-risk drill-down.
- Established data contracts, quality assertions, metric definitions, and leakage controls so analytical results can be rebuilt and explained from source.

These bullets intentionally contain no invented uplift, revenue, or accuracy numbers. Verified scale and model metrics may be added only after the pipeline is complete.

## Interview story outline

1. **Situation:** A retail bank has fragmented customer, account, transaction, product, and loan tables but lacks a governed 360 view.
2. **Task:** Build a reproducible analytical product that helps growth, customer, and risk teams ask consistent questions.
3. **Action:** Explain source audit, data grain, bridge handling, DuckDB layers, SQL metrics, cohort proxy, dashboard design, and model go/no-go.
4. **Result:** Present verified analytical findings and the decisions they inform; state limitations and proposed experiments.
5. **Reflection:** Discuss how you prevented double counting, leakage, unsupported churn claims, and false causal conclusions.
